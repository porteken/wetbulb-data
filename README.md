# Wetbulb Data Pipeline

This is the automated pipeline for processing wet-bulb temperature data and loading it into the web application. It was split out of the `pet-data` pipeline repo, so it still shares the underlying orchestration (`pipeline.py`, `load.py`, `historical_pet_update.py`) and the Postgres/S3 infrastructure with that project's PET pipeline.

1. **Compute**: PET (Physiological Equivalent Temperature) and wet-bulb temperature are computed daily per US city in parallel. PET comes from ARCO-ERA5 on Google Cloud Run (`google_era5.py`, `era5-worker`). Wet-bulb comes from NOAA's ISD Global Hourly station observations via the Davies-Jones (2008) method (`wetbulb.py`), which stores both the daily average and daily max; it's fetched from NCEI's bulk archive directly on GitHub Actions runners (`isd.py`, the default, no auth required), with NOAA LCD v2 (`lcd.py`) and NLDAS-2 gridded reanalysis (`giovanni.py` via the Giovanni Time Series API, or `nldas.py`'s original per-hour granule-download path on Cloud Run) kept as fallback sources.
2. **Store**: Workers write parquet shards directly to an AWS S3 bucket, partitioned by year.
3. **Load**: Parquet shards are COPYed into a staging table and upserted into Northflank-hosted Postgres on the `(location_id, date)` unique key, so every load is idempotent and safe to re-run.
4. **Analyze**: Materialized views in Postgres generate summary statistics, historical trend comparisons, and long-term forecasts. Yearly appends refresh the views in place (`refresh_views.py`); full rebuilds recreate them from `create_views.sql`.

## Entry points

- `pipeline.py` orchestrates the full pipeline locally (fetch → compute → load → views). `pull_all.sh`, `pull_pet.sh`, `pull_wetbulb.sh`, and `pull_both.sh` are thin wrappers around it, and the historical environment variables (`MODE`, `YEARS`, `PRODUCTS`, `USE_CLOUD_RUN`, ...) are still honored as defaults. Run `pipeline.py --help` for the full flag list; `--mode smoke` processes a single week for quick validation.
- The `yearly_update` GitHub workflow appends the previous year every early April (once ARCO's final data covers it — a pre-flight check in `build_year_range.py --check-arco` fails fast otherwise) and opens a GitHub issue if any job fails.
- The `wetbulb_backfill` GitHub workflow (`workflow_dispatch`) reruns any historical wet-bulb range via NOAA ISD, city-sharded across parallel jobs, then truncates and reloads the `wetbulb` table.

## Wet-bulb data source: NOAA ISD vs. LCD vs. NLDAS-2 (Giovanni / granules)

`pipeline.py --wetbulb-source` selects how station/grid data is fetched:

- **`isd`** (default): `isd.py` fetches each city's nearest NOAA weather station's daily CSV files from [NCEI's ISD Global Hourly bulk archive](https://www.ncei.noaa.gov/products/land-based-station/integrated-surface-database) — plain HTTPS, **no authentication**, and no rate limiting observed under sustained load. Every temperature/dewpoint/pressure element carries a per-observation quality-control code; values are rejected when the raw value is NOAA's missing-data sentinel or the QC code marks it suspect/erroneous (`{2,3,6,7}`) — see `isd.py`'s module docstring. Nearby cities that share an airport station are deduplicated to one fetch. Always runs as local subprocesses — even when `--use-cloud-run` is set for the PET/ERA5 path — writing straight to S3. This is what the `yearly_update` and `wetbulb_backfill` workflows use, for free on GitHub Actions instead of billed Cloud Run compute.
  - Each city is mapped to an *ordered list* of ISD `USAF+WBAN` candidate ids using the checked-in `cities_isd_stations.csv` (regenerate it with `make_isd_station_map.py` if `cities_lcd_stations.csv` changes; this hits NCEI over the network, no credentials needed). Multiple candidates exist per city because NCEI's own station inventory (`isd-history.csv`) both misdates USAF-id transitions and sometimes files a station-year under the same USAF paired with a `99999` WBAN placeholder — `isd.py` tries each candidate per year in order, falling through past a 404 *or* a candidate whose file exists but has zero hourly rows.
  - Wet-bulb is computed uniformly with `wetbulb_davies_jones` from station temperature/dewpoint/pressure for every year, rather than trusting NOAA's own `HourlyWetBulbTemperature` column — that field is only populated in recent years, so relying on it would create a methodological seam mid-record.
  - ISD timestamps are UTC; day boundaries (and therefore daily max/avg values) are approximated to station local standard time by shifting each station's timestamps by `round(longitude / 15)` hours, keeping day windows consistent with the LCD-derived dataset this source replaced.
  - A station-year fetch failure (network/5xx, exhausted retries) blocks only that specific year's write for the affected cities — since ISD fetches one file per station-year candidate and the gap is known precisely. A 404, a file with zero hourly rows, or a QC-rejected value is treated as a legitimate absence (not a gap), and the year is still written.
- **`lcd`** (fallback): `lcd.py` fetches the same underlying station network from [NCEI's Local Climatological Data v2 bulk archive](https://www.ncei.noaa.gov/products/land-based-station/local-climatological-data), no auth. **LCD is an *unfiltered* product with no quality-control columns at all.** A spike-error investigation found confirmed corrupt readings flowing straight into computed daily-max wetbulb — e.g. a single 154 °C dry-bulb hour reported by a Santa Rosa, CA station in Nov 2007 (producing a 39.5 °C daily-max wetbulb), and *in-range* dew-point spikes (a one-hour 32.9 °C dew-point jump against a ~18 °C baseline) that no plausibility filter can catch but ISD's QC flags remove. Kept only for comparison/rollback (`WETBULB_SOURCE=lcd` restores the prior path with zero code changes); `cities_lcd_stations.csv`/`make_lcd_station_map.py` remain checked in since `cities_isd_stations.csv` is itself derived from them.
- **`giovanni`** (fallback): fetches each city's whole multi-year hourly NLDAS-2 series from the [Giovanni Time Series API](https://api.giovanni.earthdata.nasa.gov/timeseries) in one request per variable. Requires a free NASA Earthdata account (see Credentials below). Each city is asked for the same land-snapped NLDAS-2 grid cell the granule path resolves via its static land mask, using the checked-in `cities_nldas_cells.csv` (regenerate with `make_nldas_cell_map.py`; needs the `nldas` optional dependency group and a live granule download).
- **`granules`** (fallback): the original `nldas.py` path — downloads full hourly NLDAS-2 CONUS granules over HTTPS and extracts each city's nearest grid cell. Requires Earthdata credentials; runs on Cloud Run (`nldas-worker`) when `--use-cloud-run` is set. `nldas-worker` isn't deployed by `cloudrun_provision.sh` by default — set `DEPLOY_NLDAS_WORKER=1` to deploy it.

### ISD/LCD vs. NLDAS-2: known differences

LCD/ISD are point station observations; NLDAS-2 is a 0.125° grid-cell average. A validation comparison across 15 cities spanning 2000–2025 (LCD vs. NLDAS-2) found daily-max wet-bulb MAE ≈ 1.35 °C and mean bias ≈ −0.66 °C between the two sources, stable across decades — an expected spatial-representativeness gap, not a data-quality problem. This applies to ISD too, since ISD and LCD share the same underlying station network. Also note: station hourly timestamps are approximated to local standard time (see above), while NLDAS-2 is UTC, so daily aggregation windows shift by the station's UTC offset relative to the old NLDAS-derived dataset.

## Running locally (no cloud)

The ISD wet-bulb path needs no cloud compute and no third-party credentials at all — `isd.py` runs as local subprocesses even in the default (Cloud Run/S3) configuration, and `--local` just changes where it reads/writes and skips the ERA5 Cloud Run dispatch. A full local backfill or yearly update needs only Postgres credentials (`POSTGRES_DB_URI` or `PG*`) in `.env` — no AWS, GCP, or Earthdata credentials required (those are only needed for the `giovanni`/`granules` fallback sources).

- **Full historical backfill**: `./pull_wetbulb.sh --local --truncate`. With the defaults (years 2000 → last year, 10 city shards × 2 concurrent `isd.py` processes × 8 threads each), a full ~26-year backfill for 500 cities takes roughly 30–45 minutes end to end, including the Postgres load and view rebuild.
- **Yearly/incremental update**: `./pull_wetbulb.sh --local --years 2025` (no `--truncate` — loads upsert on `(location_id, date)`, so this is safe to re-run).
- **Tuning parallelism**: total concurrent ISD requests ≈ `--isd-job-limit` × `--isd-concurrency`. NCEI's bulk archive has shown no rate limiting under sustained load (unlike the Giovanni API), so the modest defaults here are a courtesy, not a known necessity — raise them cautiously if you need a faster backfill. `--isd-city-shard-count` controls how many `isd.py` processes the city list is split across (each `--isd-job-limit` bounds how many run at once).
- **Resuming an interrupted run**: re-run the same command with `--resume-local` added. This skips wiping the local `wetbulb_data_csv/year=YYYY` output before the run, so `isd.py`'s per-shard/per-year `batch_exists` check picks up only the work that's still missing (including any individual years that hit a transient fetch gap). Only reuse this across reruns that keep `--isd-city-shard-count` the same — partition filenames encode the shard index, so changing the shard count invalidates the resume check.
- The `wetbulb_backfill` and `yearly_update` GitHub workflows remain available as a free, hands-off alternative to running locally.

## Operational notes (NCEI ISD bulk archive)

- **File GETs are fast and unthrottled; bucket LIST/HEAD requests are pathologically slow.** Never probe station-file existence with HEAD or a directory listing — `make_lcd_station_map.py` learned this the hard way and `make_isd_station_map.py` follows the same pattern. Use a small ranged GET instead.
- **A 200 response doesn't mean hourly data exists, and NCEI omits columns dynamically.** Some station-years exist but carry only daily/monthly summary rows, zero hourly METAR — `isd.py`'s `fetch_station_year` falls through to the next candidate id in that case, not just on a 404. Separately, NCEI's CSV writer omits an entire column (not just blank cells) when a station-year file has no non-null values for it (e.g. no `MA1` pressure element at all), so `isd.py` reads columns defensively rather than with a fixed `usecols` list.
- **NCEI's station inventory (`isd-history.csv`) misdates coverage.** Some stations' pre-2005 data lives under an *older* USAF id whose own inventory row claims it ended years earlier, and some station-years are filed under the same USAF paired with a `99999` WBAN placeholder instead of the station's real WBAN. `make_isd_station_map.py` builds an ordered candidate-id list per city rather than trusting the inventory dates — see its module docstring for the specific verified cases.
- **Station coverage is tiered** (inherited from the LCD map `cities_isd_stations.csv` is derived from). Most cities match a station whose archive covers the full pipeline window (`tier` 1 in `cities_lcd_stations.csv`); a handful may fall back to a shorter-record station (`tier` 2) — those cities simply have fewer years of data, same as any other station gap.

## Credentials

- **ISD** (default wet-bulb source) / **LCD** (fallback wet-bulb source): no credentials needed beyond Postgres.
- **Giovanni / granules** (fallback wet-bulb sources): need a free [NASA Earthdata](https://urs.earthdata.nasa.gov/) account with the "NASA GESDISC DATA ARCHIVE" application authorized. Set `EARTHDATA_USERNAME` and `EARTHDATA_PASSWORD` in `.env` for local runs, or as GitHub Actions / Secret Manager secrets (`cloudrun_provision.sh` wires them into the `nldas-worker` job when `DEPLOY_NLDAS_WORKER=1`).
- PET/ERA5 and all database loads still need the usual Postgres/AWS/GCP credentials regardless of wet-bulb source.
